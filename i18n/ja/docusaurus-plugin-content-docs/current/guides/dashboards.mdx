docStaticは、TinaCMSにダッシュボード機能を追加します。Tinaは、Gitリポジトリ内のファイルシステムをデータベースとして使用してGraphQL APIを生成します。ダッシュボードは、このAPI（ローカルまたはクラウド上）にクエリを実行し、CMS上で直接、実用的なレポートを表示します。ダッシュボード機能は現在、ベータ版と見なされています。 機能自体は十分にテストされていますが、ユーザーインターフェースは暫定的なものであり、さらなる改良が必要です。ダッシュボードはページが更新されると自動的に更新されます。ダッシュボードを表示した後、他のユーザーが変更を加えた場合は、**\[Refresh]**をクリックしてダッシュボードを更新できます。

<Admonition type="note" title="Note">
  Depending on the amount of content in the system, some dashboards may take some time to load. These dashboards will typically update slightly faster when running locally.
</Admonition>

## ダッシュボードの表示

CMS から「ダッシュボード」コレクションに移動します。ページ上部には、GraphQL 接続の状態を示すステータスバーがあります。これには、クラウドに接続されているか、localhost に接続されているかが表示されます。localhost が利用可能な場合、常に localhost に接続されます。クラウドを使用するには、ローカルの開発サーバーが停止していることを確認してください。 ステータスバーには環境情報も表示され、すべての設定が有効であるかどうかも確認できます。

## ワークフローのステータスの確認

「コンテンツ概要」ダッシュボードには、/docs パス内のトピックの総数と、各ワークフローステータスにあるトピック数が表示されます：

* 下書き
* レビュー中
* 翻訳中
* 承認済み
* 公開済み
* 非公開

ステータスリンクをクリックすると、そのステータスにあるすべてのトピックが表示されます。

\[編集] をクリックすると、トピックを開いて編集できます。

\[閉じる] アイコンをクリックすると、トピックの一覧を閉じることができます。

### 最近のアクティビティの確認

\[最近のアクティビティ] セクションには、最近変更されたトピックが表示されます。 期間（「全期間」、「先週」、「先月」）を絞り込み、表示件数を5件から50件まで設定できます。

## 翻訳ステータスの確認

「翻訳」ダッシュボードには、リストから選択した言語について、各トピックのステータスが表示されます：

* 最新： 翻訳の最終更新日がソースファイルの最終更新日よりも新しい場合。
* 古い：ソースファイルの最終更新日が翻訳の最終更新日よりも新しい場合。
* 欠落：対応する翻訳ファイルがないソースファイルが存在する場合。

## コンテンツの再利用の確認

「コンテンツの再利用」ダッシュボードには、システム内の再利用可能なコンテンツとその使用箇所が表示されます。 以下の4つのカテゴリについて報告します：

* コードスニペット：CodeSnippetコンポーネントによって参照されているコードファイル。
* 用語集用語：用語集コレクションで定義されている用語。
* スニペット：Snippetコンポーネントによって参照されているMDXコンテンツファイル。
* 変数セット：VariableSetコンポーネントによって参照されている変数セット。

カテゴリカードをクリックすると、そのカテゴリ内のアイテム一覧と、各アイテムが使用されているトピックが表示されます。

### 再利用の提案の表示

「コンテンツ再利用」ダッシュボードの「提案」セクションでは、再利用可能なコンポーネントに変換できる可能性のあるコンテンツを特定します：

* スニペット候補（コード）：トピック内のインラインコードブロックで、コードスニペットファイルとして抽出できるもの。
* 用語候補：トピック内にプレーンテキストとして表示されている用語で、代わりにGlossaryTermコンポーネントを使用できるもの。
* スニペット候補（重複テキスト）：2つ以上のトピックに表示されているテキストブロックで、スニペットファイルとして抽出できるもの。
* 変数候補：トピック内にプレーンテキストとして表示されている変数値で、代わりに「VariableSet」コンポーネントを使用できるもの。

提案カードをクリックすると、検出された項目とそれらが含まれるトピックを確認できます。

## メディアの再利用状況の確認

メディアライブラリのダッシュボードでは、/static/img パス内のコンテンツがどこで使用されているかが表示されます。ファイルと画像の総数、ファイルサイズ、画像のパス、および画像サイズが表示されます。

以下の条件でフィルタリングできます：

* すべてのコンテンツ。
* 画像のみ。
* 最近（7日間）。
* 使用済み。
* 未使用。

使用済みのコンテンツについては、「n件のドキュメントで使用済み」をクリックすると、そのコンテンツが使用されているトピックが表示されます。その後、「編集」をクリックして、それらのトピックを編集できます。

## リンク切れの確認

「リンク切れ」ダッシュボードでは、トピック内のハイパーリンクについて、HTTPステータスを含むレポートが表示されます。これにより、404または500を返すページはリンク切れとして識別されます。

このダッシュボードには、前回のチェック結果が表示されます。ブラウザでは他サイトへのリンクのHTTPステータスを読み取ることができないため、ダッシュボード自体ではチェックは実行されません。 リンクを確認するには、以下を実行してください：

```bash
yarn check-links
```

これにより、すべての外部リンクがリクエストされ、各サーバーからの応答が記録され、レポートが更新されます。最新の結果が必要なときはいつでも実行してください。ダッシュボードには、前回のチェックの日時が表示されます。

レポートでは以下がカウントされます：

* リンクの総数。
* OK：サーバーから成功またはリダイレクトステータスが返されたリンク。
* 破損：サーバーから 404 Not Found や 500 Internal Server Error などのエラーステータスが返されたリンク。これらは修正が必要なリンクです。
* 未確認：応答が返されなかったため、リンクの状態を判断できなかったもの。 原因としては、ドメインの解決に失敗した場合、リクエストがタイムアウトした場合、サイトが403でリクエストを拒否した場合、429によるレート制限などが挙げられます。これらはリンク自体ではなく、チェックを実行しているマシン側の問題である可能性もあるため、ハイパーリンクをクリックして手動で検証してください。
* 未チェック：リクエストされていないリンク。これには、内部リンク、アンカー、`mailto:` および `tel:` リンク、ローカルホストのアドレスが含まれます。
* スキャンされたファイル。

内部リンクは、サイトの構築段階で実際のページリストと照合して検証され、破損しているものが報告されるため、ここでは意図的にリクエストされません。 localhostアドレスもスキップされます。これは、localhostアドレスがチェックを実行しているマシン上でたまたま実行されているものを指すためです。localhost URLをドキュメントに記載しても、報告されることはありません。

ダッシュボードには、問題のあるリンクを含むファイルが一覧表示されます。どちらのリストでも「編集」をクリックしてファイルを開くことができます。

例えば継続的インテグレーション（CI）ジョブなどで、リンク切れが見つかった場合にビルドを失敗させるには、`yarn check-links --strict` を実行してください。これにより、リンク切れの場合のみエラーで終了し、検証されていないリンクについてはエラーになりません。そのため、一時的なネットワークの問題によってビルドが失敗することはありません。
