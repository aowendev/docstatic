# Verwendung von Claude in diesem Projekt

[Claude Code](https://claude.ai/code) ist Anthropics KI-gestützte CLI. Es wird in diesem Projekt als Entwicklungsassistent für die unten beschriebenen Aufgaben eingesetzt.

Die Aufteilung der Verantwortlichkeiten ist wichtiger als die Liste der Aufgaben. Claude schlägt Optionen vor, vertritt eine davon und schreibt den Code. Jede Entscheidung, die das Produkt prägt – was gebaut wird, welcher Ansatz gewählt wird, was ausgeliefert wird – trifft der Projektverantwortliche. Wenn eine Designentscheidung Konsequenzen hat, die der Verantwortliche abwägen sollte, wird von Claude erwartet, den Kompromiss offenzulegen, anstatt ihn stillschweigend zu treffen.

## Entwurf und Entwicklung von Funktionen

Claude arbeitet an vollständigen Funktionen, nicht nur an isolierten Änderungen. Die Scaffolding-CLI und das Template-Sync-Tooling, der Chatbot mit seiner austauschbaren Provider-Unterstützung, das System zur Wiederverwendung verwalteter URLs und die gemeinsame Datenschicht der Dashboards wurden alle auf diese Weise entwickelt: Claude recherchiert den bestehenden Code, schlägt ein Design vor und setzt es um, sobald der Ansatz vereinbart ist.

Das schließt die Konzeptionsarbeit ein. Datenstrukturen, Build- und Laufzeitgrenzen sowie die Struktur neuer Subsysteme werden von Claude entworfen und vor Beginn der Umsetzung überprüft. Entwürfe werden häufig zurückgewiesen, manche werden komplett verworfen.

## Automatisierung manueller Aufgaben

Claude übernimmt repetitive oder geskriptete Arbeiten, die sonst manuellen Aufwand erfordern würden – zum Beispiel das massenhafte Aktualisieren von Frontmatter-Feldern in vielen Dateien, das Umformatieren von Inhalten für eine neue Struktur oder das Generieren von Boilerplate-Code, der einem bekannten Muster folgt. Dies sind Aufgaben, bei denen die Form der Arbeit klar ist, die Ausführung jedoch mühsam ist.

## Entwicklung von React-Komponenten und Dashboards

Claude wird verwendet, um React-Komponenten und Daten-Dashboards zu schreiben und zu iterieren. Dazu gehören die Implementierung neuer UI-Komponenten, die Anpassung von Layout und Styling sowie die Anbindung von Daten aus der TinaCMS GraphQL-API. Claude arbeitet innerhalb der bestehenden Komponentenmuster des Projekts, anstatt neue Abstraktionen einzuführen.

## Definition von CMS-Schemas

Claude schreibt die TinaCMS-Collection- und Template-Definitionen, die die Bearbeitungsformulare steuern, einschließlich der Feldvalidierung und der Regeln, die Felder abhängig von anderen Werten ein- oder ausblenden.

## Schreiben von Tests

Claude schreibt und pflegt die Testsuite des Projekts. Tests sollen das Verhalten anhand einer maßgeblichen Quelle prüfen – eines externen Standards, einer Spezifikation oder der tatsächlich erzeugten Ausgabe – statt lediglich zu wiederholen, was der Code bereits aussagt.

## Fehlersuche

Claude hilft dabei, die Ursache von Fehlern einzugrenzen, indem es relevanten Code liest, aktuelle Änderungen überprüft und über wahrscheinliche Ursachen nachdenkt. Es ist besonders nützlich bei Fehlern, die sich über mehrere Dateien erstrecken oder bei denen die Konfiguration mit dem Verhalten abgeglichen werden muss.

## Schreiben von Stilregeln

Claude wird verwendet, um Vale-Regeln für das docStatic-Stilset zu schreiben. Dies umfasst das Verfassen neuer Regeln, deren Test gegen Beispielinhalte und die Verfeinerung von Mustern zur Reduzierung falsch positiver Ergebnisse. Die Regeln werden in `.vale/styles/docStatic/` neben der Dokumentation gespeichert.

## Pflege der Informationsarchitektur

Claude hilft bei der Pflege der Informationsarchitektur des Dokumentensatzes – durch Überprüfung von Taxonomie, Tags und Seitenstruktur, um eine konsistente Kategorisierung und logische Navigation zu gewährleisten. Dies ist eine fortlaufende Aufgabe, die typischerweise parallel zu Inhaltsüberprüfungen durchgeführt wird.

## Inhaltliche Konsistenzprüfung

Claude überprüft die Dokumentation auf faktische Konsistenz, strukturelle Lücken und logischen Fluss. Dies ist eine leichtgewichtige Überprüfung – sie ersetzt keine formelle redaktionelle Überprüfung, ist aber nützlich, um offensichtliche Probleme zu erkennen, bevor der Inhalt die Überprüfer erreicht.

## Dokumentationsentwürfe

Gelegentlich erstellt Claude einen ersten Entwurf einer Dokumentationsseite, der dann von einem menschlichen Autor überprüft und bearbeitet wird. Entwürfe werden als Ausgangspunkte behandelt, nicht als fertiger Inhalt.

<Admonition type="note" title="Änderungen validieren">
  Bevor eine Arbeit als abgeschlossen gilt, führt Claude `yarn lint` (Biome) für Codeänderungen und `vale` für Änderungen an der Dokumentation aus und behebt alles, was eines der beiden Tools meldet.
</Admonition>

<Admonition type="note" title="Umfang der KI-Beteiligung">
  Konzept, Produktrichtung und Prioritäten von docStatic liegen in der Verantwortung des Projektverantwortlichen. Claude trägt zur Konzeption und Umsetzung einzelner Funktionen innerhalb dieser Richtung bei, und seine Arbeit wird vor der Integration überprüft. Zum Zeitpunkt der Erstellung ist Claude Mitautor von etwa sechs Prozent der Commits.
</Admonition>
