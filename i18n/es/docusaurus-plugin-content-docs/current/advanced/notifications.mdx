# Notificaciones

docStatic utiliza <Url urlKey="github-actions" /> para enviar notificaciones de flujos de trabajo. En la carpeta `.github/workflows/` se incluyen ejemplos de notificaciones de revisión y traducción. Para activarlas, es necesario realizar cierta configuración en GitHub. También puedes utilizarlas como punto de partida para desarrollar tus propias notificaciones personalizadas.

## Correo electrónico

Las acciones `email-review.yml` y `email-translate.yml` se activan cuando se añaden las etiquetas «review» o «translate» a un archivo Markdown de la rama principal. Para utilizarlas, añade estos <Url urlKey="github-use-secrets" linkText={[{ lang: "es", text: "secretos" }]} /> a tu repositorio:

* `SMTP_SERVER`
* `SMTP_PORT`
* `SMTP_USERNAME`
* `SMTP_PASSWORD`
* `NOTIFY_EMAIL_TO`
* `NOTIFY_EMAIL_FROM`

Puedes obtener esta información de tu proveedor de correo electrónico. Por ejemplo:

* <Url urlKey="icloud-mailserver" /> (requiere una <Url urlKey="apple-app-specific-passwords" linkText={[ { lang: "es", text: "contraseña específica para la aplicación)" }]} />.
* [Outlook](https://support.microsoft.com/en-us/office/pop-imap-and-smtp-settings-for-outlook-com-d088b986-291d-42b8-9564-9c414e2aa040)

## Slack

Las acciones `slack-review.yml` y `slack-translate.yml` utilizan los mismos desencadenantes que las versiones de correo electrónico. Para utilizarlas, añade la URL de tu webhook de Slack como un secreto denominado `SLACK_WEBHOOK_URL`. Para obtener más información, consulta [Envío de mensajes mediante webhooks entrantes](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/) en la documentación de Slack.

## Teams

Las acciones `teams-review.yml` y `teams-translate.yml` funcionan igual que las versiones de Slack. Microsoft va a dejar de dar soporte a la aplicación **Incoming Webhooks** para Teams a partir de diciembre de 2025, pero actualmente no existe un método disponible públicamente en GitHub para enviar Adaptive Cards a los flujos de trabajo. La solución alternativa es utilizar `curl`:

```yaml
- name: Send Teams test notification
  run: |
    curl --ssl-no-revoke -X POST \
    --location ${{ secrets.MS_TEAMS_HTTP_POST_URL }} \
    --header 'Content-Type: application/json' \
    --data '{ \
      "type": "message", \
      "attachments": [{ \
        "contentType": "application/vnd.microsoft.card.adaptive", \
        "content": { \
          "$schema": "http://adaptivecards.io/schemas/adaptive-card.json", \
          "type": "AdaptiveCard", \
          "version": "1.3", \
          "body": [ { \
            "type": "TextBlock", \
            "text": "This is a test notification from GitHub Actions (Teams).", \
            "wrap": true }]}}]}'
```

1. En Teams, ve al canal al que quieras enviar mensajes, haz clic en los tres puntos (**…**) y selecciona **Flujos de trabajo**.
2. Haz clic en **Administrar**.
3. Haz clic en **Nuevo flujo**.
4. Busca plantillas para webhooks y haz clic en **Enviar alertas de webhook a un canal**.
5. (Opcional) Edita el **Nombre del flujo**.
6. Inicia sesión y haz clic en **Siguiente**.
7. Selecciona un **Equipo** y un **Canal** de las listas y haz clic en **Crear flujo**.
8. Copia el `MS_TEAMS_HTTP_POST_URL`, guárdalo como un secreto en GitHub y haz clic en **Hecho**.

<Admonition type="tip" title="Consejo">
  Puedes utilizar la acción de GitHub «Probar notificaciones» para comprobar tus conexiones.
</Admonition>
